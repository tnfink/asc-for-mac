## Motivation

The game does not have an icon: the app shows macOS's generic app icon in the Dock, the
Finder and the app switcher, and the mounted release `.dmg` (TASK-0014, `scripts/create-dmg.sh`)
shows the standard disk icon. A nice looking icon that resembles the game
(<https://www.asc-hq.org>) makes the app recognisable as Advanced Strategic Command and makes
the port look like a finished Mac app, before it is published (TASK-0029).

## Task description

Create one nice looking icon that resembles the game (<https://www.asc-hq.org>) and use it as
the icon of the app, in the About window and as the volume icon of the release `.dmg`.

Known facts:

- The app currently has no icon and no asset catalogue; its `Info.plist` is generated by Xcode
  (`GENERATE_INFOPLIST_FILE = YES` in `ASCforMac.xcodeproj/project.pbxproj`).
- The About window (`app/ASCforMac/AboutView.swift`, SwiftUI) shows only text today, no icon.
- `scripts/create-dmg.sh` creates `build/release/ASC-for-Mac-<version>.dmg` without a volume
  icon.
- ASC already has icon and logo graphics that show its style and can serve as model or source
  material: `thirdparty/asc/data/icons/program-icon.png` (32x32), `thirdparty/asc/data/icon_asc.gif`
  (32x32), `thirdparty/asc/data/asc.ico` (32x32 and 16x16 only), `thirdparty/asc/data/logo640.pcx`
  and `thirdparty/asc/installer/installer-logo.png` (150x177). They are too small to be scaled
  up to 1024x1024 directly. They are GPL-licensed like the rest of ASC (`thirdparty/asc/`); the
  icon may build on them. Do not change files in `thirdparty/asc/`.
- ASC sets a window icon itself at runtime: `thirdparty/asc/source/sg.cpp` calls
  `app.setIcon("program-icon.png")`, which ends in `SDL_SetWindowIcon`
  (`thirdparty/asc/source/libs/paragui/src/core/pgapplication.cpp`). On macOS, SDL replaces the
  Dock icon of the running app with such an icon. As far as the code shows, ParaGUI rejects
  this icon ("Icon must have a palette!", the file is RGBA), so the Dock icon is not replaced;
  verify this with the running app. If ASC's icon does replace the new one, prevent it with a
  minimal, marked change (see `doc/thirdparty.md`) or in the facade.
- The website <https://www.asc-hq.org> shows the look of the game (hex maps, futuristic
  military units such as tanks, aircraft and ships).

To do:

1. Design the icon so that it resembles ASC and looks good at all sizes macOS uses (from 16x16
   up to 1024x1024). The icon must be compliant with the macOS style guide: Apple's Human
   Interface Guidelines for app icons
   (<https://developer.apple.com/design/human-interface-guidelines/app-icons>), in the version
   that applies to macOS 27. Check the current guidelines when implementing; among others they
   cover the system-defined rounded-rectangle shape, the grid and safe area, a simple
   recognisable motif instead of detailed screenshots or text, and the system appearances
   (default, dark, clear and tinted). Prefer the icon format and tool Apple recommends for the
   current macOS (e.g. an Icon Composer `.icon` file, which Xcode compiles into the app; Icon
   Composer comes with Xcode). An Icon Composer file is a folder with a JSON description and
   layer images, so it can also be written by a script. Create the icon only with the tools in
   `doc/developerInfrastructure.md` (e.g. Xcode's tools, or a Python script without extra
   packages); add any other tool there first (e.g. `sips`/`iconutil`, which ship with macOS).
2. Put the icon's source and the generated images into the repository (the app's files go to
   `app/ASCforMac/`, a script that generates it to `scripts/`) and set it as app icon in the
   Xcode project.
3. Show the app icon in the About window (`AboutView.swift`) above the app's name, taken from
   the app itself (e.g. `NSApp.applicationIconImage`), not from a second copy of the image.
4. Give the volume of the release `.dmg` the new icon in `scripts/create-dmg.sh` (a
   `.VolumeIcon.icns` at the volume's root with the custom-icon flag set), generated from the
   same source as the app icon, and test it in `scripts/test.sh`.
5. Show the icon to the user (e.g. as rendered image at several sizes and in the appearances)
   and let the user accept it before the task is done, since "nice looking" is the user's
   judgement.
6. Record the icon and its origin (own work and/or derived from which ASC files): in
   `scripts/sbom-components.json` (comment of the package that contains the icon, e.g.
   `own-code` for files in `app/` and `scripts/`), so that `doc/sbom.spdx.json` and the licence
   information shown in the app cover it (see TASK-0024, TASK-0025), and in `doc/thirdparty.md`
   if it is derived from ASC's graphics.

Out of scope: icons for documents or other file types, and changing ASC's own in-game graphics.

## Implementation notes

- **Icon:** `app/ASCforMac/AppIcon.icon` (Icon Composer document): an olive background gradient,
  the layer group "Hex field" (pointy-top hex of ASC's map, translucent glass) and the group
  "Unit" (an aircraft seen from above), as SVG layers. Motif after ASC's program icon
  `thirdparty/asc/data/icons/program-icon.png`; no image data of ASC is used. The user accepted
  the look (preview of all appearances and of 16 to 128 pixels) on 2026-11-24.
- **ASC's runtime icon:** the assumption in *Known facts* was wrong in its reasoning: ASC calls
  `SDL_SetWindowIcon` through its own `ASC_PG_App::setIcon` (`source/paradialog.cpp`), which has
  no palette check. Checked with the running game: the user saw the new icon in the Dock, the
  app switcher and the About window, so no change in `thirdparty/asc/` was needed
  (documented in `doc/thirdparty.md`, *App icon*).
- **Finder:** checked with `NSWorkspace.icon(forFile:)` on a fresh copy of the built app (the new
  icon). An app built earlier without icon at the same path shows a cached generic icon until
  the bundle is touched (documented in `doc/buildAndTest.md`, *App icon*).
- **Check against Apple's Human Interface Guidelines for app icons** (version of
  2026-10-28, read from developer.apple.com):

  | Guideline | How it was checked |
  |-----------|--------------------|
  | Layered icon in Icon Composer format, preferred for macOS | `AppIcon.icon` with a background and two foreground groups; `assetutil --info` shows the layer groups in `Assets.car` |
  | Square, unmasked layers; the system masks the rounded rectangle | SVG layers on a square 1024x1024 canvas without own mask; renders show the system mask |
  | Primary content centred, avoid truncation | Hex and aircraft centred at (512, 512); ictool renders show nothing cut off by the mask |
  | Simple motif, minimal number of shapes, simple background | Two filled shapes (hex, aircraft) on a two-colour gradient |
  | Clearly defined edges, no extremely thin lines or sharp corners | Filled polygons with rounded joins (`stroke-linejoin="round"`); render at 16 and 32 pixels still recognisable |
  | No text, no photos, no screenshots or UI replicas | Only the two graphic shapes |
  | Let the system handle highlights, shadows, blur | No effects in the SVGs; only Icon Composer's glass, neutral shadow and translucency settings |
  | Vector graphics for layers | Both layers are SVG |
  | Consistent features in default, dark, clear and tinted appearances | Rendered with ictool as `Default`, `Dark`, `ClearLight`, `ClearDark`, `TintedLight`, `TintedDark`; hex and aircraft remain visible and the same in all six |
  | 1024x1024 layout, sRGB | Canvas 1024x1024, colours as sRGB in `icon.json` |
