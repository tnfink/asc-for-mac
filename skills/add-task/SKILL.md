# add-task

Creates a new task file in `aitasks/` and fills it with all information the user provided.
The file itself is always generated by `scripts/tasks.sh new`; never create task files by hand
and never pick a task ID yourself.

## 1. Collect the information

Take everything the user said about the task (and any material they referenced, e.g. an issue
text, a document in `doc/` or code) and sort it into the sections of a task:

| Section               | Content                                                              | If not given                          |
|-----------------------|----------------------------------------------------------------------|---------------------------------------|
| Short description     | One line, ideally under 60 characters, no pipe character or line breaks     | Derive it from the request            |
| External link         | URL of an external task, e.g. a Jira issue                           | `none`                                |
| Dependencies          | IDs of tasks that must be done first, e.g. `TASK-0002, TASK-0005`    | `none`                                |
| Motivation            | Why the task is important, what problem it solves, who benefits      | Derive it from the request            |
| Task description      | What needs to be done, constraints, relevant files, out of scope     | Derive it from the request            |
| Acceptance criteria   | Concrete, verifiable conditions for the task to be done              | Derive them from the task description |

Rules:

- **Use all given information.** Do not drop details the user mentioned; put each into the
  section where it fits best. Keep the user's wording for requirements and constraints.
- **Do not invent requirements.** When you derive content, stay within what the user asked for.
  Write motivation and acceptance criteria that follow directly from the request.
- **Dependencies:** run `scripts/tasks.sh list` and check that every referenced task ID exists.
  If the user names a dependency by description instead of ID, look it up in that list.
  If a dependency cannot be found, ask the user.
- **Ask only when necessary:** if it is unclear what the task is about at all, ask the user
  before creating the file. Otherwise create the task and mention any assumptions you made.
- If the user describes several independent tasks, create one task per piece of work and
  link them via dependencies where one needs the other.

## 2. Generate the task file

```bash
scripts/tasks.sh new "<short description>"
```

The script prints `Created <ID>: <path>`. Use exactly that ID and path from here on.

## 3. Fill in the task file

Edit the generated file:

- Replace the placeholder comments (`<!-- ... -->`) in **External link**, **Dependencies**,
  **Motivation**, **Task description** and **Acceptance criteria** with the content from step 1.
  Remove the placeholder comments you replaced, including the example acceptance criteria.
- Write acceptance criteria as a checklist (`- [ ] ...`), one verifiable condition per line.
  Prefer criteria that can be checked by a command, a test or an inspection. Do not repeat
  criteria that apply to every task; they are defined in `doc/aiTaskDefinitionOfDone.md`
  (e.g. that the documentation is updated) and checked by `implement-task`.
- The new task must fulfill `doc/aiTaskDefinitionOfReady.md`.
- If the new task has to be done before existing tasks, renumber the tasks so the numbers still
  show the order, as described in `AGENTS.md`.
- **Do not change** the rows **ID**, **Short description** and **Status** in the header table,
  the title line, or the **History** section. `scripts/tasks.sh` reads the header rows and has
  already recorded the creation in the history.
- Keep the status `open`. Creating a task does not mean starting it.

## 4. Verify and report

1. Run `scripts/tasks.sh list open` and check that the new task appears with the correct
   ID and short description.
2. Report the task ID and file path to the user, together with a short summary of the task
   and any assumptions you made.

Do not start working on the task unless the user explicitly asks for it.
